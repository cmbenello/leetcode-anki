LeetCode Anki — Settings

Scheduling intervals

How long after grading before the problem is due again. Use suffixes like 30m, 2h, 3d, or 1d12h. Bare numbers are minutes.

Growth multiplier — applied to the previous interval on each repeat. Floors at the base interval above. Higher = faster spacing.

Daily reminder

Get a Chrome notification listing the problems due today. Click it to open the popup view.

GitHub sync

Optional. Auto-commits each grade to a repo of your choice. Create an empty GitHub repo first, then paste a Personal Access Token with the repo scope. Generate a token.

Defaults

Import your LeetCode history

Pulls every submission from your LeetCode account (newest first) using your existing login, so you need to be signed in to leetcode.com in Chrome. It opens a LeetCode tab in the background if none is open. Solved problems count toward your goals, fill in the growth view and daily tracker, and teach the recommender. You won't get a flood of reviews: imported problems join your review queue a few a day, longest-ago first. Running it again later only adds what's new.

NeetCode

Your NeetCode progress syncs automatically. Open neetcode.io while logged in and visit any practice list (NeetCode 150, 250, …). The extension reads the completed list NeetCode keeps in your browser, read-only, and marks those problems solved. NeetCode doesn't record dates, so these problems sit at the centre of the growth view and don't show in the daily tracker. Goals can track NeetCode 150 and NeetCode 250 directly.

Prep phases

Name the stretches you prepared for something, such as an interview loop, and the growth view can show each one on its own. A problem belongs to the phase it was first solved in. Anything outside every phase, or solved only on NeetCode (which keeps no dates), is Unstructured. Leave the end blank while a phase is still going.

Repair mis-detected submissions

Older versions guessed verdicts from the page and sometimes logged a stale "Accepted" from your submission history, or gave a problem the title of the one before it. This removes verdict bursts (several results seconds apart — only the last was real) and fixes titles that don't match their problem. Verdicts read from LeetCode's judge are never touched. Runs automatically once on update; safe to re-run.

Repair card URLs

For older cards stored before site detection existed, this scans each card's slug against LeetCode's GraphQL. Slugs found there get site: leetcode and a leetcode.com URL. Slugs not found get site: neetcode and a neetcode.io URL. Skips cards that already have a stored URL (those are fine).

Data

Drill export — every attempt in the shape of Drill's attempts table (one JSON object per line, items as lc:<slug>, with the model's prediction, topics, and attempt factors). Also committed to the tracker repo as drill/attempts.jsonl on every sync.
